# ur-kit 开发

1. 先读仓库根目录 `AGENTS.md`，核对 `contracts/manifest.json` 的 SaaS 来源提交。
2. 合同只通过 `python3 scripts/sync_contracts.py --saas <saas-path> --sha <full-sha>` 更新；先运行对应 SaaS 服务的 `build.sh` 并提交生成物，再以该提交导出。即使 Swagger 已有字段，也要核对生成的 Go HTTP 请求类型和实际 HTTP→RPC 转换；仅看 `.api` 或 Swagger 无法证明服务会接收并透传字段。重复运行 `build.sh` 核对生成结果稳定。
3. `web-shared/` 只通过 `scripts/sync_web_shared.py` 按固定 SaaS 提交更新。同步后运行 `scripts/configure_web_workspace.py`、`pnpm install --frozen-lockfile`、`pnpm -r run stub --if-present` 和 `pnpm --filter org-iot-client build`；快照适配逻辑写回同步脚本。
4. 先运行 `python3 scripts/generate_java_pb.py` 两次核对消息与 gRPC 服务 Stub 哈希，再验证 Go/Java/Node 的 HTTP、RPC 示例、Java Maven 编译、`things/sdk/seed` 幂等性及重复生成无差异，最后才发布标签。`sdks/node` 位于外层 pnpm workspace，独立安装使用 `pnpm install --ignore-workspace --frozen-lockfile`，避免把 38 个项目全装进 SDK 验证目录。Linux x86_64 的 gRPC Java 插件固定版本并校验 SHA-256；其他平台设置 `UR_KIT_GRPC_JAVA_PLUGIN`。迁移 SaaS Go pb 时，相同 `.proto` 的新旧生成包不能同进程加载；按服务入口执行 `go list -deps`，确认只剩一种生成包，标签发布后再验证脱离本地替换的普通构建。检查旧客户端 `apilegacy` 受影响字段与鉴权。
   HTTP 输入、ID、空值、时间与错误响应以 `sdks/conformance/README.md` 和共同样本为准；三语言客户端改动后一起核对。
5. Web 和 mobile 位于 `apps/iot-basic/`，改动客户端请求时一起核对合同版本。迁仓后检查开发说明、脚本注释和命令是否仍指向 SaaS 旧目录；可在 Git 跟踪文件中检索 `apps/web/apps/org-iot-client`、`apps/mobile-uniapp` 与个人绝对路径。mobile 有独立锁文件，但位于外层 pnpm workspace 之下；在 `apps/iot-basic/mobile` 执行 `pnpm install --ignore-workspace --frozen-lockfile`，否则 pnpm 会安装外层 38 个项目而不创建 mobile 的 `node_modules`。随后运行 `pnpm run tsc`、`pnpm run test:contract` 与目标端 `pnpm run build:mp-weixin`；构建时由环境注入 `VITE_MP_WEIXIN_APPID`。不要复制私有环境配置。
6. `cache/common.LayeredCache` 通过 `LayeredOptions` 注入 Redis、事件总线和业务 loader，保留 `cache:<name>:<key>` 与 `server.cache.sync.<name>`；旧回源不能在失效后重新发布，事件广播必须在发布锁外。`cache/platform` 的企业 `tenant` Hash、在线状态和 IM 游标可注入 `cache/redis`；企业资料使用完整 JSON 并核对 Hash 字段与 JSON `code`，不要截断平台扩展字段。游标必须由 Redis 原子比较 64 位十进制 ID，不得经 Lua 浮点数转换。变更时运行 `go test -race ./cache/...`。`upstream/` 仅为 SaaS 源码对照快照，含私有导入的包不得当作可发布 SDK。
7. `apps/iot-basic/Dockerfile` 从仓库根上下文构建 Web 与 Go，运行阶段只包含静态页面和 Go 二进制。`web/.env.production` 提供可公开的本地构建默认值，目标平台数字应用 ID 必须在构建时通过 `VITE_GLOB_APPID` 覆盖；不要依赖被忽略的开发机 `web/.env`。后端集成测试在 `apps/iot-basic/backend` 执行，镜像测试核对 Web 深层路径、样例业务接口、平台路径代理和健康检查；`mobile` 独立构建，不进入运行镜像。
8. `things/sdk/protocol/{runtimeconfig,cloud,core,mqtt,tracking}` 是已解耦的启动配置读取/合并、云配置生命周期、配置/产品/设备分页 RPC、外部产品 ID 映射、设备主子协议配置选择、协议注册心跳、可注入周期调度、MQTT 收发与会话跟踪。原 `backend/things/sdk` 的全部受版本控制源码由 `scripts/sync_things_sdk.py` 从合同锁定提交同步到 `things/sdk/upstream`，运行 `--check` 核对逐文件字节与清单；物模型原始源码由 `scripts/sync_schema.py` 单独维护。`tracking.ActiveAll` 沿旧协议会话索引汇总近三十天活动设备，只有活动记录而无 MQTT 会话的产品不进入结果。协议自有 gRPC 服务通过 `core.Options.RPCRegistrars` 注册，需同时设置 `RPCListenAddr`，并在 `RPCServerOptions` 注入身份认证、权限和日志拦截器；反射仅在明确设置 `RPCReflection` 时启用。非 MQTT 设备调用 `core.ReportConnection` 发布上下线，不写 MQTT 会话。外部资源通过 `core.AddStopHandle` 注册退出回调，协议停止后拒绝再注册。`runtimeconfig.Resolve` 的未找到和空配置保留本地默认值，其他 RPC 错误不能静默吞掉；运行配置与云配置 RPC 的身份上下文由接入方提供。分页未读完或解码失败不得提交部分配置或产品映射；`cloud.ForEachConfig` 拒绝产品空页、重复 ID 和总数变化，`cloud.GRPCDeviceSource.ForEachDevice` 按产品分页并检查跨产品、重复设备，单设备同步失败继续处理且汇总错误，但已执行的回调不会自动回滚。`core.Timer` 的同一任务下处理器逐个执行并汇总失败；`core.GRPCTimerScheduler` 用公开 timed pb 注册任务，接入方必须提供带授权的 RPC 客户端与真实事件总线。Paho 适配器先 `Connect` 再订阅，`ResumeSubs` 只恢复待确认的订阅，已确认订阅需在 OnConnect 重连回调重新订阅。修改时运行 `go test -race ./things/sdk/protocol/...` 和 `go vet ./things/sdk/protocol/...`。Broker 集成测试需设置 `UR_KIT_TEST_MQTT_BROKER`；原 `things/sdk/upstream/protocol` 尚有 SaaS 私有导入，平台联调未完成，不能仅凭子模块测试宣称完整协议 SDK 可发布。
9. `things/sdk/cache` 用公开 `dm` RPC 客户端封装产品与设备资料、产品/设备 TSL JSON 的 TTL 缓存。缓存键显式包含企业编码，接入方用匹配该企业的真实授权上下文发起查询，并在平台产品/设备变更事件中显式调用失效方法；资料响应若带不匹配的企业编码会被拒绝，返回的 protobuf/JSON 均为副本。`TSLCache` 按设备条目覆盖产品同名条目并保留扩展字段，产品变更失效已访问的设备模型。完整物模型纯值语义从合同锁定的 SaaS 提交通过 `python3 scripts/sync_schema.py --saas <saas-path> --sha <full-sha>` 同步到 `things/sdk/schema`，`upstream/schema` 留原始快照；同步两次必须哈希一致。原始快照可能含 CRLF，须保持源字节与校验和一致，`.gitattributes` 已为该路径配置 `whitespace=cr-at-eol`。`ProductModel` / `DeviceModel` 严格校验并构建索引，空或无效功能定义会报错；`schema/repo.go` 的接口类型已迁入，原私有设备标识替换为等形的 `schema/compat/devices.Core`，具体数据库实现和 SaaS 调用点仍待迁移。修改时运行 `go test -race ./things/sdk/cache/... ./things/sdk/schema/... ./cache/common/...`，不得把未校验的 JSON 聚合结果直接替换内部模型。
10. `protocols/modbus` 的独立 TCP 样例提供保持寄存器读与单寄存器写，`Simulator` 是仅供本地测试的设备；运行 `go run ./protocols/modbus/cmd/demo` 验证完整读写流程，再运行 `go test -race ./protocols/modbus/...` 核对功能码 3/6、设备回显和异常码；原 Modbus 服务源码仍在 `upstream/` 对照，样例不等于完整服务迁移。
11. Go、Node、Java HTTP/RPC 中间件在认证前过滤平台内部身份字段 `ithings-user`、`ithings-user-role`、`ithings-tenant-code`、`ithings-project-id`、`ithings-meta`、`ithings-set-token`；Go/Java RPC 客户端转发已有元数据时也要过滤。`ithings-token`、`token`、`tenant-code`、`project-id` 是令牌和选择上下文，须保留并交认证器核验。JDK `HttpExchange` 原请求头不可修改，业务处理器只能收到过滤包装。修改时同时运行 Go、Node、Java 中间件与基本应用代理测试，并核对结构监测代理过滤列表。
12. Go `PlatformAuthenticator`、Node `createPlatformAuthenticator` 与 Java `UrPlatformAuthenticator` 通过平台用户自身信息核验企业成员，带 `project-id` 时再核验项目列表的正授权；所有三语言 HTTP 客户端的令牌请求都拒绝重定向，Go 注入的自定义 `http.Client` 也不得覆盖此边界。Java 使用 `UrMiddleware.httpScoped` / `rpcScoped` 注入。三者只提供身份范围，不替代应用的资源动作授权器。Go 基础应用示例直接使用公共认证器，修改时连同示例运行竞态测试。
13. 云协议入口用 `cloud.NewRuntime` 串接 `core.Protocol`、`GRPCConfigSource`、`ConfigManager`、可选更新订阅和 `core.Timer`：服务先注册，配置全量拉取成功后才订阅通知和注册周期任务；任何后续启动失败都释放已生效资源。设备同步先用 `cloud.RegisterDeviceSync` 将产品主/子协议配置选择及设备分页回调登记到 Timer，再启动 Runtime；每个设备失败后继续遍历并汇总错误，已执行的设备动作不会回滚。更新订阅必须提供取消函数。`Stop` 取消订阅、停止协议并等待当前定时处理器退出；平台调度任务是持久记录，其删除由接入方负责，停止后的残留触发不得再执行协议处理器。修改时运行 `go test -race ./things/sdk/protocol/...` 与 vet。
