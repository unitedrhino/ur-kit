# 通用业务页面与定时文档报告

ur-kit 可以用于报告、文件、任务等普通业务应用。复用页面布局、鉴权、请求、表单、表格和状态交互时，设备与项目范围按业务需要接入。本文是开发约定与报告场景设计；下述任务服务和 API 是待实现方案，不能当作现有运行能力。

## 1. 页面按使用流程组织

| 页面类型 | 通用交互 | 定时报告中的用途 |
| --- | --- | --- |
| 列表页 | 搜索、筛选、分页、权限控制、空态、行操作 | 模板列表、计划列表、生成记录、文件列表 |
| 编辑页或抽屉 | 基础信息、参数表单、校验、保存反馈 | 编辑模板、数据范围、输出格式、执行周期 |
| 详情页 | 概要、内容区域、状态、关联记录 | 报告详情、生成记录、失败原因 |
| 步骤表单 | 分步校验、返回修改、提交状态 | 选择模板 → 数据与时间范围 → 周期与格式 → 确认 |
| 执行状态区 | 排队、执行阶段、结果、失败重试 | 后台生成进度；刷新后从服务端恢复 |
| 文件展示区 | 类型、版本、大小、预览、下载、有效状态 | Markdown / DOCX 附件与可读报告 |

复用已有组合和交互，业务页面传入自己的数据、筛选项和操作；当同一能力确实出现多处复用时再提取组件。不要先造一套通过任意 JSON 描述所有页面的引擎。任务、文件和状态组件不应要求设备 ID，也不应在组件内部读固定 IoT API。

新页面沿用项目自有 UI、语义颜色、响应式布局和统一错误反馈。新增组件以中文写明 props、emits、slots；请求成功后刷新相关列表和统计，筛选和任务详情可通过 URL 恢复。图表、编辑器和预览器按需加载。

**上下文按页面声明。** 企业级报告只要求企业身份和相应权限；仅当数据来自项目时才要求选择项目。多项目汇总逐个核验项目可见性。现有 IoT 客户端的[项目入口守卫](../../../../apps/iot-basic/web/src/router/guard.ts)会加载项目并触发选择/创建流程，独立业务应用需按自己的路由范围调整守卫及请求头，不可直接复制后假定“无项目也能进入”。本条是接入要求，当前 IoT 守卫行为未因此改变。

## 2. 定时生成 Markdown / DOCX 的页面

建议在自己的应用下建立“报告”模块，保留四个清晰入口：

1. **报告模板**：名称、说明、章节、数据来源和模板版本；支持预览样例。模板可以读取普通业务数据，产品/设备选择仅是可选数据来源。
2. **生成计划**：选择模板、数据范围、统计周期、执行时区、输出格式；显示下一次执行时间，支持启停与立即生成。显示易读的执行说明，如“每天按所选时区生成上一完整自然日的报告”；需要高级调度表达式时再提供高级入口。
3. **生成记录**：显示触发方式、统计时间范围、执行状态、耗时、失败原因和文件结果；可以进入详情或按权限重试。
4. **报告查看**：显示正文及关联附件。Markdown 提供可读预览与原文下载；DOCX 提供原文件下载，可按需求增加转换预览。格式转换失败不阻断已经成功生成的其他文件。

移动端复用同一业务 API，优先提供查看计划、生成记录、正文预览、下载/打开和必要的立即生成操作；复杂模板编辑按产品需要开放，不强制照搬桌面布局。

## 3. 后端职责与数据对象

以下是自己应用的推荐对象，不新增平台合同，也不要求修改 ur-kit 的平台生成客户端：

| 对象 | 最小职责 |
| --- | --- |
| `ReportTemplate` | 模板内容/结构、版本、数据参数及可选生成器类型 |
| `ReportSchedule` | 模板引用、企业/可选项目范围、时区、周期、启停和下一次触发时间 |
| `ReportRun` | 计划触发或手动请求、固定的模板/参数/统计窗口快照、执行状态和尝试记录 |
| `ReportArtifact` | 所属执行、格式、文件标识、大小、内容摘要、生成状态和有效期 |

处理流程为：调度触发 → 幂等创建执行 → 后台领取任务并重验数据权限 → 读取数据 → 形成报告内容 → 按格式渲染 → 持久化文件与结果 → 页面查看/下载。HTTP 提交只返回执行 ID，不让浏览器长连接承担整个生成过程。浏览器关闭后任务继续运行。

- 调度优先复用部署平台实际开放的任务服务，也可以注入自己应用的调度器；明确需要的 RPC、事件订阅和服务权限。没有开放平台调度能力时，不假设普通 HTTP 账号可以直接调用内部 timed 服务。数据库保存计划和执行，前端倒计时只用于显示。
- 调度重复触发用“计划 ID + 本次计划触发时刻”唯一键去重；手动生成使用调用方请求标识。多实例用数据库领取/租约等机制避免重复执行，服务重启后恢复未完成任务。
- 明确时区、夏令时、错过触发和同一计划重叠执行的处理策略；创建执行时固定统计时间窗口，例如上一完整自然日，重试不再按当前时间重新计算窗口。
- 模板修改产生新版本，历史报告保留当时版本和输入范围。重试保留失败记录与尝试次数；暂停计划停止未来触发，正在执行的任务是否取消由明确操作决定。
- 由应用自己的 `ReportRenderer` 类接口按格式选择实现；内容先形成稳定的报告结构或 Markdown，再分别生成真实文件。DOCX 必须是可被 Word/兼容工具打开的 OOXML 文档，不能给 Markdown 改扩展名。表格、中文、图片等按所需功能验证。
- 生成可来自规则和数据模板；只有产品要求时才接入 AI。需要 AI 时记录模型/提示模板版本、来源和失败状态，不把 AI 依赖写死在通用页面。

执行状态可采用 `queued → running → succeeded / partial_failed / failed / cancelled`。同时生成多种格式时按附件保存结果，只有部分格式失败则记录 `partial_failed`，成功附件仍可下载；重试失败格式需沿用本次内容快照。

## 4. 自有 API 草案

例如自己的业务前缀为 `/api/v1/my-app/`，可按以下职责定义 POST JSON 接口。路径仅为设计示例，当前基础后端未提供这些端点：

| 操作 | 请求要点 | 返回要点 |
| --- | --- | --- |
| `report/template/get-list`、`save` | 分页、模板字段、编辑版本 | 模板列表或已保存版本 |
| `report/schedule/get-list`、`save`、`set-enabled` | 计划、周期、时区、范围 | 计划及服务端计算的下次执行时间 |
| `report/run/create` | 模板/计划、参数、格式、幂等请求标识 | 执行 ID、当前状态 |
| `report/run/get-list`、`get-one` | 分页/筛选或执行 ID | 状态、统计窗口、尝试与附件摘要 |
| `report/run/retry` | 执行 ID、待重试格式、请求标识 | 原执行关联的重试状态 |
| `report/artifact/get-download` | 附件 ID | 已鉴权文件流或短期下载地址 |

业务 JSON 响应沿用应用的统一信封；附件下载使用正确 MIME 与 `Content-Disposition`。ID 无损传递，时间单位和时区字段在 Web、移动端与后端保持一致。文件保存在持久存储中，容器临时目录仅作生成中间文件，容器重建后仍能查看历史结果。

创建计划、立即生成、重试、查看和下载分别核验业务权限及企业/项目范围；后台使用专用服务身份，每次执行重新核验授权范围。知道附件 ID 不等于有权下载，签名地址也不能代替签发前的鉴权。Markdown 预览沿用过滤后的渲染器；DOCX 预览按需转换，不把内部报告自动提交给外部预览服务。

## 5. 当前源码可复用的部分

- [共享组件目录](../../../../web-shared/packages/saas/src/components)：表单/列表组合、步骤外壳等可作为实现参考；是否可导入以当前标签的 `package.json` 导出为准，不猜测组件 API。
- [报告 Markdown 渲染](../../../../web-shared/packages/saas/src/components/ai-chat/report-markdown.ts)：现有安全展示逻辑，可按稳定导出复用或按源码归属提取；它不是 Markdown/DOCX 文件生成服务。
- [现有报表页面](../../../../web-shared/packages/saas/src/views/report/index.ts)：电子表格设计/渲染能力，不能直接当作定时文档任务后台；还需核对平台是否开放对应 `/api/v1/view/` 路径，当前基础应用代理仅放行 system/things/data。
- [基础后端](../../../../apps/iot-basic/backend/main.go)：HTTP、平台认证、平台代理和静态页入口；持久计划、worker、文档渲染和文件持久化需要在业务后端实现。

新增共享源码遵循套件来源规则：SaaS 维护的 `web-shared` 快照通过维护者同步；使用方先在自己的应用放业务组合，确有复用需求再回归共享源。前端、worker 和文件生成器在 Web+Go 的同一应用镜像内装配时，也须在 Dockerfile 中包含真实需要的运行依赖，并保持健康检查和优雅退出。

## 6. 场景验收

在真正实现此功能时，至少验证：设置计划后关闭页面仍能按时生成；重复触发和多实例不重复产出；跨日/时区窗口及服务重启恢复正确；手动生成、暂停和失败重试有真实状态；Markdown 可读，DOCX 可打开且正文/表格一致；只失败一种格式时另一种仍可下载；越权用户无法查看或下载；容器重建后历史附件仍有效。

调度与统计窗口用可控时钟验证，状态与文件用后台集成测试验证；页面验证保存后自动刷新、切换范围不串数据、刷新能恢复详情和按钮权限。文档设计通过不能记为报告任务已实现，模拟生成通过也不能记为真实调度和文件交付已验收。
