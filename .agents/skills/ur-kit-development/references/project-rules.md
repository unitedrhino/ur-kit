# 自己仓库的 AI 开发规范

## 带入公开指南

`AGENTS.md` 是自动发现入口，技能正文按任务加载。复制应用骨架时，把 ur-kit 的 `.agents/skills/ur-kit-development/` 整个目录（含 `references/`）一并带入；不要只复制 `SKILL.md` 后留下断链，也不要依赖开发机上的 SaaS 路径。

使用 `ur skills download --skill ur-kit-development --url <固定技能ZIP地址> --json` 下载维护者打包的技能时，按返回 `localPath` 复制整个目录；该命令需使用支持 `--skill` 的 CLI。包内源码链接已经固定到公开提交，可直接在新仓中使用。`ur skills install/update` 管理的是 API 操作技能，不会替你升级开发技能。

直接从源码复制时，指南中的相对源码链接按 ur-kit 原目录布局编写。改变布局或仅通过依赖使用 SDK 时，将它们改成**所固定标签**的 GitHub 文件链接，或自己仓内的对应文件；安装依赖不等于自动安装 AI 技能。维护细则可留作套件维护参考，应用开发不需要执行其中的 SaaS 同步流程。

下面是自己的 `AGENTS.md` 起点，提交前将占位符替换为项目实际值，并删除不适用的端：

```markdown
# 项目开发规范

- SDK：github.com/unitedrhino/ur-kit，固定版本 <标签及提交>；接口合同与该版本一致。
- 入口：读取 .agents/skills/ur-kit-development/SKILL.md，按当前任务加载协议或应用指南。
- 目录：<Web/mobile/backend 或协议服务的实际目录和职责>。
- 边界：本仓处理 <业务范围>；Core/Things 平台能力通过公开 SDK 或明确平台代理路径接入。
- 不导入 SaaS 私有模块或 upstream 原始快照，不改生成代码和版本锁来绕过合同差异。
- 认证：外部身份由平台认证器核验，资源动作由本应用授权器检查；按企业/项目隔离数据。
- 合同：大整数 ID 无损传递，明确空值、时间单位、错误码；接口变化更新文档和定向测试。
- 配置：地址、凭据、证书由运行环境注入，示例使用占位符；禁止记录 token/密钥。
- 代码：新增/修改的定义以中文说明用途与边界；复杂流程补关键分支、并发和失败处理说明。
- 验证：<本仓可直接执行的安装、定向测试、构建及 Docker/Compose 命令>。
- 交付：记录 SDK/镜像版本、实际测试结果和未完成项；先本地验收，远程部署另行明确环境。
```

## 验收时回答这些问题

| 检查 | 完成条件 |
| --- | --- |
| 是否可独立开发 | 全新检出后不需要私有源码、个人绝对路径或本机未提交文件；所有导航和命令匹配当前布局 |
| 版本是否确定 | SDK、合同、Web 共享包和生成工具均锁定；构建不自动改锁 |
| 是否有真实权限 | 空令牌、伪造内部身份、跨企业/项目、非法资源动作都有拒绝用例 |
| 协议是否闭环 | 实际上报后读回；实际控制后查设备与平台结果；断线恢复和上下线通过 |
| 应用是否闭环 | 登录、上下文切换、业务读写、页面直达/刷新和错误反馈通过；移动端在目标端验收 |
| 是否能交付 | 实际构建运行镜像、健康检查与 API 验证通过；有不可变版本与回滚方式 |

资料不齐时，AI 先从仓库确认已有事实；缺少厂家报文、点表、平台接入权限或产品业务规则时明确询问。可以先完成不依赖它们的本地实现，但不能把模拟运行或跳过的测试写成真实平台/硬件通过。
