# 统一信令内部 RPC 合同更新

合同及原始快照固定来源为 SaaS 提交 `36e516625a8ebc0deb2e853239eb90129a589ad6`，实际来源与逐文件摘要见 `contracts/manifest.json`。本说明不表示任何新标签已经发布。

## 兼容性

本次不新增 RPC 方法、不改旧字段编号或类型。追加以下内部消息字段：

- AgentAudio：可信原会话保持截止、保持请求及实际确认、协商支持标志；内置父设备实时节目工具的可用范围。
- DeviceDelivery：IPC 与 Focus 预检的当前物理连接实例及其精确回显。

旧客户端省略字段时仍保持零值；`parent_media_tools` 缺省与“已知但不可用”的空消息不同，不能在转发中混淆。新保持协商不成功或原实例回显为空时，不得推断对端支持新能力。SDK 只提供合同编码，实际授权、期限、幂等及媒体门由平台服务负责；这些字段不能由外部设备自填来取得权限。

同源快照同时保留主线已有合同，例如通知幂等键、项目附件与结构告警接口；不能只复制两个 Proto 而保留错误的旧来源清单。原始快照不属于独立可消费的服务端代码。

## Java 生成工具

Java 编译器明确固定为 `libprotoc 25.6`，对应 `protobuf-java 3.25.6`。使用 `UR_KIT_JAVA_PROTOC` 指定独立可执行文件，生成器在改写产物前验证版本。旧系统编译器生成的代码可能被当前 Java 运行库的安全检查拒绝；不要降级运行库或开启不安全旧代码兼容开关。安装与固定摘要见 [Java SDK](../../sdks/java/README.md)。Go 服务的系统 Proto 工具无需因此替换。

## 消费与升级

使用新字段的消费者应锁定包含本更新的正式 SDK 标签；发布前的本地工作区验证不等于正式版本可下载。不要在同一 Go 进程中同时加载 SaaS 私有与 ur-kit 公开的同名 protobuf 生成包。

平台应先具备新 AISVR 保持策略和 DMS 实例核验能力，再让 IM 新路径使用；旧节点未支持时新路径保持明确拒绝或未知，不影响旧独立语音，不能以忽略新增字段当作支持。新 SDK 本身不修改生产配置、设备 Topic 或设备消息方法。
